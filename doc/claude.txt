1. INTRODUCTION                                             *claude-introduction*

claude.vim opens the Claude CLI in a terminal split inside Vim. Any number of
sessions can run at once, each with a name you choose; the session panel
(|claude-session-panel|) lists them all, grouped by project, worktree and
branch. You can send the current file or a visual selection to Claude for
explanation, switch models on the fly, and navigate between your code and the
Claude windows using a small set of commands and key mappings.

==============================================================================
2. REQUIREMENTS                                             *claude-requirements*

  - Vim 8.1+ (with |+terminal|)
  - The `claude` CLI installed and on $PATH
    (https://docs.anthropic.com/en/docs/claude-code)
  - `rg` (ripgrep) on $PATH for @ file completions in the input window
    (https://github.com/BurntSushi/ripgrep)

3. CONFIGURATION                                           *claude-configuration*

All variables are optional. Set them in your |vimrc| before the plugin loads.

------------------------------------------------------------------------------
                                                          *g:claude_split_anchor*
g:claude_split_anchor~
  Which screen edge the Claude window is pinned to.

  Values:   'right' (default), 'left', 'top', 'bottom'
  Example: >
    let g:claude_split_anchor = 'bottom'
<
------------------------------------------------------------------------------
                                                           *g:claude_split_size*
g:claude_split_size~
  Width in columns for left/right splits, or height in lines for top/bottom
  splits.

  Default: 80
  Example: >
    let g:claude_split_size = 100
<
------------------------------------------------------------------------------
                                                                 *g:claude_cmd*
g:claude_cmd~
  Shell command used to launch the Claude CLI.

  Default: 'claude'
  Example: >
    let g:claude_cmd = '/usr/local/bin/claude'
<
------------------------------------------------------------------------------
                                                          *g:claude_panel_width*
g:claude_panel_width~
  Width of the session panel, in columns.

  Default: 35

------------------------------------------------------------------------------
                                                         *g:claude_panel_anchor*
g:claude_panel_anchor~
  Which edge the session panel is pinned to.

  Values:  'left' (default), 'right'

------------------------------------------------------------------------------
                                                          *g:claude_panel_icons*
g:claude_panel_icons~
  Status glyphs, keyed 'active', 'idle' and 'closed'. A partial dictionary is
  merged over the defaults.

  Example: >
    let g:claude_panel_icons = {'active': '>>'}
<
------------------------------------------------------------------------------
                                                          *g:claude_panel_ascii*
g:claude_panel_ascii~
  Set to 1 to force the plain [A] / [I] / [C] glyphs. Done automatically when
  'encoding' is not a Unicode encoding.

  Default: 0

------------------------------------------------------------------------------
                                                     *g:claude_panel_refresh_ms*
g:claude_panel_refresh_ms~
  How often, in milliseconds, session status is polled while the panel is
  visible. The poller is stopped entirely when the panel is hidden, so this
  costs nothing when the panel is closed.

  Default: 2000

------------------------------------------------------------------------------
                                                      *g:claude_panel_idle_secs*
g:claude_panel_idle_secs~
  Seconds without terminal output before a running session is shown as idle
  rather than active. Consulted only when the bottom of the terminal says
  nothing conclusive; see the two patterns below.

  Default: 30

------------------------------------------------------------------------------
                                                    *g:claude_panel_working_pat*
g:claude_panel_working_pat~
  Pattern marking a session as working, matched against the bottom rows of its
  terminal — where Claude prints its spinner while it runs.

  Default: 'esc to interrupt'

------------------------------------------------------------------------------
                                                    *g:claude_panel_waiting_pat*
g:claude_panel_waiting_pat~
  Pattern marking a session as waiting for you: a numbered choice, a
  permission question, a yes/no. Matching sessions are collected under
  "Needs you" at the top of the panel and counted in its header.

  Both patterns track another program's output, which is not this plugin's to
  promise, so both are yours to change. A pattern that stops matching costs
  the state, never a wrong answer: the session falls back to
  |g:claude_panel_idle_secs|.

  Default: '\%(^\|\n\)\s*>\=\s*1\.\s\|Do you want\|(y/n)'
           (the first alternative matches Claude's numbered choices)

------------------------------------------------------------------------------
                                                    *g:claude_panel_stale_days*
g:claude_panel_stale_days~
  Days after which a finished session is hidden from the panel, whoever named
  it. 0 hides none. `I` reveals them (|claude-unnamed|).

  Default: 2

------------------------------------------------------------------------------
                                                     *g:claude_panel_done_rows*
g:claude_panel_done_rows~
  How many finished sessions the Done group draws before it stops with a
  `... N more` row. Distinct from |g:claude_panel_closed_limit|, which caps
  how many transcripts are read from disk in the first place: how much is
  scanned and how much is drawn are different questions.

  Default: 10

------------------------------------------------------------------------------
                                                    *g:claude_panel_show_closed*
g:claude_panel_show_closed~
  Set to 0 to list only live sessions, hiding resumable ones.

  Default: 1

------------------------------------------------------------------------------
                                                   *g:claude_panel_closed_limit*
g:claude_panel_closed_limit~
  Maximum number of closed (resumable) sessions listed per project.

  Default: 10

------------------------------------------------------------------------------
                                                         *g:claude_panel_height*
g:claude_panel_height~
  Height in lines the panel is given when it first comes to share a column
  with NERDTree, which takes the remaining lines.

  This is a starting size, not an enforced one: resize the window by hand and
  it stays where you put it.

  Default: 15
  See also: |claude-nerdtree|

------------------------------------------------------------------------------
                                                     *g:claude_panel_height_pct*
g:claude_panel_height_pct~
  The same height as a percentage of the screen (|'lines'|), which is what the
  panel uses by default so the column keeps its proportions on any terminal.

  Set to 0 to size the panel in lines with |g:claude_panel_height| instead.

  Default: 25
  See also: |claude-sidebars|

------------------------------------------------------------------------------
                                                  *g:claude_difftree_height_pct*
                                                      *g:claude_difftree_height*
g:claude_difftree_height_pct~
g:claude_difftree_height~
  The diff tree's height in the shared sidebar column: as a percentage of the
  screen, or — when the percentage is 0 — in lines.

  Like the panel's, this is a starting size rather than an enforced one.

  Defaults: 40 (percent), 15 (lines)
  See also: |claude-sidebars|

------------------------------------------------------------------------------
                                                 *g:claude_panel_nerdtree_stack*
g:claude_panel_nerdtree_stack~
  When 1 (default), the panel and NERDTree share a single column with the
  panel on top. Set to 0 to leave them as separate side-by-side columns.

  Default: 1
  See also: |claude-nerdtree|

------------------------------------------------------------------------------
                                                       *g:claude_difftree_store*
g:claude_difftree_store~
  Path of the JSON file remembering each branch's diff base.

  When empty (the default) it lives at `data/difftree.json` inside the plugin
  directory, and carries the same warning as |g:claude_session_store|: a plugin
  update or reinstall removes it. Point it somewhere durable to keep the
  bases: >
    let g:claude_difftree_store = expand('~/.claude/vim-difftree.json')
<
------------------------------------------------------------------------------
                                                      *g:claude_panel_auto_open*
g:claude_panel_auto_open~
  Set to 1 to open the session panel automatically on |VimEnter|.

  Default: 0

------------------------------------------------------------------------------
                                                        *g:claude_session_store*
g:claude_session_store~
  Path of the JSON file that remembers session names.

  When empty (the default) the file lives at `data/sessions.json` inside the
  plugin directory, which keeps the plugin self-contained.

  WARNING: a plugin update or reinstall — `:PlugUpdate`, `:PlugClean`, or
  deleting the bundle directory — removes that file and every session name
  with it. Point this at a durable location to keep names across updates: >
    let g:claude_session_store = expand('~/.claude/vim-sessions.json')
<
  If the file cannot be written the plugin warns once and keeps names in
  memory for the rest of the Vim session.

------------------------------------------------------------------------------
                                                  *g:claude_session_prompt_name*
g:claude_session_prompt_name~
  When 1 (default), starting a session asks for a branch and then a name
  (see |claude-workspaces|); the panel's `n` asks for the name only. Set to 0
  to skip every prompt: the session gets no workspace and no name, Claude
  names the conversation itself, and the row is buried once it finishes (see
  |claude-unnamed|).

  Default: 1

------------------------------------------------------------------------------
                                                        *g:claude_session_flags*
g:claude_session_flags~
  Whether the CLI supports `--session-id` and `--name`, which the plugin uses
  to mint a session id up front and share the session's name with Claude.

  -1 (default) probes `claude --help` once. Set to 1 to force the flags on or
  0 to force them off — needed only when |g:claude_cmd| launches Claude
  through a wrapper with a different name, so the probe cannot run safely.

  Default: -1

4. COMMANDS                                                     *claude-commands*

------------------------------------------------------------------------------
                                                                  *:ClaudeOpen*
:ClaudeOpen
  Focus a Claude session, starting one if none is running. When several are
  running the session under the cursor wins; otherwise a picker appears
  (see |claude-session-target|).

------------------------------------------------------------------------------
                                                                   *:ClaudeNew*
:ClaudeNew [name]
  Start a new session even when others are already running. Without an
  argument the branch and then the name are prompted for, and the branch
  decides whether the session gets a workspace of its own
  (see |claude-workspaces|).

------------------------------------------------------------------------------
                                                                *:ClaudeRename*
:ClaudeRename [name]
  Rename a session. Without an argument the new name is prompted for. The name
  is remembered across Vim restarts (see |g:claude_session_store|).

------------------------------------------------------------------------------
                                                            *:ClaudeWorkspaces*
:ClaudeWorkspaces
  List the workspaces of this repository and choose the one to work in.
  NERDTree is re-rooted onto the choice, and sessions started without a branch
  run there. See |claude-workspaces|.

------------------------------------------------------------------------------
                                                              *:ClaudeSessions*
:ClaudeSessions
  Toggle the session panel. See |claude-session-panel|.

------------------------------------------------------------------------------
                                                          *:ClaudeSessionsOpen*
                                                         *:ClaudeSessionsClose*
:ClaudeSessionsOpen
:ClaudeSessionsClose
  Open or hide the session panel explicitly. Hiding the panel never stops a
  session.

------------------------------------------------------------------------------
                                                              *:ClaudeSidebars*
:ClaudeSidebars
  Raise the whole sidebar column at once — the session panel, the git diff
  tree and NERDTree, stacked in that order — or dismiss all three when they
  are already showing. Mapped to |g:claude_sidebar_toggle_key| (<C-a> by
  default). See |claude-sidebars|.

------------------------------------------------------------------------------
                                                                *:ClaudeToggle*
:ClaudeToggle
  Toggle a Claude window. Hides it if currently visible; shows it if hidden;
  opens a new session if none exists. The Claude process keeps running while
  the window is hidden.

------------------------------------------------------------------------------
                                                                 *:ClaudeClose*
:ClaudeClose
  End a session: stop its process and wipe its terminal buffer. The
  conversation stays on disk and can be reopened with |:ClaudeResume| or from
  the session panel.

------------------------------------------------------------------------------
                                                               *:ClaudeExplain*
:ClaudeExplain
  Send the entire current file to Claude with an "Explain this file" prompt.
  Opens Claude first if no session exists. Use the visual-mode mapping
  (|<leader>ce|) to explain a selection instead.

------------------------------------------------------------------------------
                                                                 *:ClaudeModel*
:ClaudeModel
  Open an interactive numbered list to switch the model for the current
  session. Sends `/model <name>` to Claude after selection. Opens Claude
  first if no session is running.

  See also: |claude-models|, |g:claude_models|

------------------------------------------------------------------------------
                                                                 *:ClaudeInput*
:ClaudeInput
  Toggle the input window for composing multi-line messages. If the window is
  already open, the content is discarded and the window closes.

  Press <C-s> to send the buffer contents to Claude; press CTRL-C (normal
  mode) to save the draft and hide the window; press `q` (normal mode) to
  discard the draft and close.

  Opens a new Claude session automatically if none is running.

  See also: |claude-input|

------------------------------------------------------------------------------
                                                                 *:ClaudeFocus*
:ClaudeFocus
  Move the cursor to a Claude window and enter insert mode. Opens a new
  session if none exists, reveals a hidden window if the session is alive but
  not displayed, and resumes the session if it has ended.

------------------------------------------------------------------------------
                                                               *:ClaudeWinLeft*
:ClaudeWinLeft
  Move the cursor to the window on the left (equivalent to <C-w>h).

------------------------------------------------------------------------------
                                                              *:ClaudeWinRight*
:ClaudeWinRight
  Move the cursor to the window on the right (equivalent to <C-w>l).

------------------------------------------------------------------------------
                                                                *:ClaudeWinUp*
:ClaudeWinUp
  Move the cursor to the window above (equivalent to <C-w>k).

------------------------------------------------------------------------------
                                                              *:ClaudeWinDown*
:ClaudeWinDown
  Move the cursor to the window below (equivalent to <C-w>j).

5. MAPPINGS                                                     *claude-mappings*

Default mappings (disabled when |g:claude_no_default_mappings| is set):

  <leader>co    Open Claude (|:ClaudeOpen|)
  <leader>cn    Start a new session (|:ClaudeNew|)
  <leader>ct    Toggle Claude window (|:ClaudeToggle|)
  <leader>cx    Close Claude (|:ClaudeClose|)
  <leader>cf    Focus Claude window (|:ClaudeFocus|)
  <leader>cs    Toggle the session panel (|:ClaudeSessions|)
  <leader>cw    Choose the workspace to work in (|:ClaudeWorkspaces|)
  <C-a>         Raise or dismiss the whole sidebar column (|:ClaudeSidebars|).
                Normal mode only, so |CTRL-A| still increments a number under
                the cursor from a terminal buffer, from insert mode, and in
                visual mode. Rebind or disable it with
                |g:claude_sidebar_toggle_key|.
  <leader>ce    Explain current file (normal mode) or selection (visual mode)
  <leader>ci    Toggle input window (|:ClaudeInput|)
  <leader>cm    Switch model (|:ClaudeModel|)
  <leader>ch    Move cursor left  (|:ClaudeWinLeft|)
  <leader>cl    Move cursor right (|:ClaudeWinRight|)
  <leader>ck    Move cursor up    (|:ClaudeWinUp|)
  <leader>cj    Move cursor down  (|:ClaudeWinDown|)

Inside the Claude terminal window:

  <Esc><Esc>    Enter terminal-normal mode (lets Vim handle mouse and
                selection). Single <Esc> is passed through to Claude so it
                can dismiss pagers and menus.

To define your own mappings after disabling defaults: >
  let g:claude_no_default_mappings = 1
  nnoremap <silent> <F5> :ClaudeToggle<CR>
  xnoremap <silent> <F5> :<C-u>call claude#explain('v')<CR>
<

6. SESSION PANEL                                          *claude-session-panel*

|:ClaudeSessions| (or |<leader>cs|) toggles a panel on the left of the screen
listing every Claude session: the ones running in this Vim instance and the
ones that have ended but can still be resumed from their transcript.

The panel has two views, swapped with `g`.

The state view                                        *claude-panel-state*
  What each session is doing. This is what the panel opens on, because with
  several agents running the question is almost always "which one is waiting
  for me?" — and only this view answers it without being asked. >

    Claude Sessions           2 waiting

    v Needs you (2)
      * pick a diff base        wt . 2m
      * rerun the tests?      root . 5m
    v Working (1)
      o panel rework          root . 1m
    v Idle (1)
      . user_interface        root . 2h
    > Done (10)

    ? help
<
  Four groups, always in this order: Needs you, Working, Idle, Done. A group
  with nothing in it is not drawn — except Done, which is always listed while
  the registry holds a finished session, folded shut (|claude-panel-done|).

  Each row ends with the workspace the session lives in and how long ago it
  last stirred, so a state-grouped row still says where it is.

The place view                                        *claude-panel-place*
  Where the sessions live: project, then worktree, then the branch that was
  checked out when the session started. Worktrees of one repository share a
  single project node. Press `g` for it, and `g` again to come back. >

    Claude Sessions           2 waiting

    v claude-pluing
      v ~/Workspace/vim/claude-pluing
        v main
          o panel design           1m
          . doc rewrite            2h
        v feature/session-registry
          . registry spike         4h
      v ~/Workspace/vim/wt-hotfix
        v hotfix/e947
          x E947 repro             2d

    ? help
<
  Each view keeps its own folds, so swapping back and forth loses neither.

Status                                                *claude-panel-status*
  The glyph before each name is what the session is doing:

  waiting  the terminal is showing a question — a permission prompt, a
           numbered choice, a yes/no. These sessions are what "Needs you"
           collects, and the header counts them
  active   the process is working, or has produced output recently
  idle     the process is running, is not asking anything, and has been quiet
           for |g:claude_panel_idle_secs|
  closed   the process is not running here; the conversation can be resumed

  Waiting and working are read from the bottom rows of the session's terminal,
  where Claude prints its own state, using |g:claude_panel_waiting_pat| and
  |g:claude_panel_working_pat|. When neither matches, the idle timer decides,
  as it did before those patterns existed.

  Status is polled only while the panel is visible; hiding it stops the poller
  completely.

The Done group                                        *claude-panel-done*
  Finished sessions. It starts folded, draws at most
  |g:claude_panel_done_rows| of them with a `... N more` row for the rest, and
  hides the ones nobody named or nobody has touched for
  |g:claude_panel_stale_days| days (|claude-unnamed|). It reports how many it
  is hiding, and `I` reveals them.

Finding one                                           *claude-panel-filter*
  `/` filters every group by what a row could be recognised by: its label, its
  workspace and its branch. Groups left empty are dropped, folds that hid a
  match are opened, and the hidden tail is searched too — a row you asked for
  by name is not a row to hide. The header shows the active filter in place of
  the count; `/` with an empty answer clears it.

Colours~
  The panel borrows NERDTree's palette so the two halves of the sidebar look
  like one thing: group nodes are coloured like directories, session names
  like files, and the header like NERDTree's root line. Where NERDTree's own
  highlight groups exist they are used directly, so restyling NERDTree
  restyles the panel; otherwise the same underlying groups are used, and the
  colours are identical without NERDTree installed.

  Override any of these to restyle just the panel: >
    highlight link ClaudeSessionHeader     Title
    highlight link ClaudeSessionProject    Statement
    highlight link ClaudeSessionWorktree   Directory
    highlight link ClaudeSessionBranch     Directory
    highlight link ClaudeSessionMarker     Directory
    highlight link ClaudeSessionName       Normal
    highlight link ClaudeSessionNameClosed NonText
    highlight link ClaudeSessionWaiting    WarningMsg
    highlight link ClaudeSessionActive     Number
    highlight link ClaudeSessionIdle       Comment
    highlight link ClaudeSessionClosed     Comment
    highlight link ClaudeSessionHelp       String
<
  A link you set yourself is never overwritten.

Keys inside the panel~
  <CR>, o      Open the session, or fold a group node
  i            Open the session in a horizontal split
  s            Open the session in a vertical split
  t            Open the session in a new tab
  n            Start a session where the cursor is — the workspace of the row,
               or of the worktree it sits under — asking only what to call it
  N            Start a session, asking for a branch and then a name
               (|claude-workspaces|)
  g            Swap the top level: state <-> place
  /            Filter every group (|claude-panel-filter|)
  r            Rename the session under the cursor
  d            End the session (its transcript is kept, so it can be resumed)
  D            Purge: delete the session's transcript and stored name
  R            Rescan transcripts and rebuild the tree
  I            Show or hide the buried sessions (|claude-unnamed|)
  <Space>, za  Fold or unfold the node under the cursor
  q            Hide the panel
  ?            Toggle the inline key reference

A session that is already visible is jumped to rather than opened twice,
except with `t`, which always makes a new tab. Sessions open beside the panel;
the panel window itself is never replaced.

Hiding the panel does not stop anything. A session ends only when you run
|:ClaudeClose|, press `d` in the panel, or quit Vim.

Reopening a closed session~
  Claude writes a conversation to disk only once it has content, so a session
  you started but never sent a message to leaves nothing to resume. Opening
  such a session claims its id for a fresh conversation instead of failing —
  the panel entry, its name and its id are kept, and only the (empty) history
  is lost. Sessions that do have a transcript are resumed normally.

Branches listed                                       *claude-diff-branches*

The diff tree lists one row per branch directly under the project, with
directories and files below. A worktree holds exactly one branch, so it never
gets a level of its own; it is named in the branch's label instead:

  main                      checked out in the main worktree
  hotfix/e947 (wt-hotfix)   checked out in a linked worktree
  feature/x (no worktree)   commits but no checkout: committed changes only

Branch names are yellow. A branch with no remote-tracking branch — work that
exists only on this machine — is greyed instead, which is applied with a text
property since the fact is not visible in the row's text.

The branch checked out in the repository's main worktree comes first, with no
suffix. It is what makes your own uncommitted work visible: a
branch has no committed changes against itself, so while you sit on the base
branch every other rule would skip your checkout and the panel would be empty.
The node is hidden when there is genuinely nothing to show.

When a branch is the base, the committed half of the diff is taken against its
upstream instead, so commits you have not pushed still appear. With no upstream
configured, only uncommitted work is listed.

Each branch can be diffed against a base of its own. Press `b` on a branch row
to set it, or clear it with an empty answer; |:ClaudeDiffBase| does the same
from the command line. The choice is remembered across Vim restarts in
|g:claude_difftree_store|, keyed by repository so the same branch name in two
repositories keeps separate bases. `B` sets a default for the session, used
only by branches with no base of their own.

A branch diffing against something other than the default shows it in brackets
before the name, e.g. `[feature/alpha] feature/delta (beta)`.

The branches it lists are the union of three things:

  - every worktree, from `git worktree list`;
  - every branch a Claude session has run on, live or closed, taken from the
    session registry. A session records its branch when it starts, so work on
    a branch you have since moved off stays visible;
  - the branch currently checked out, if neither of the above covered it.

A branch equal to the base is skipped, since it would diff against itself, and
a branch deleted since its session ran is dropped.

A worktree is never skipped for being on the base branch — it is a place
uncommitted work can live whatever branch it holds. A session branch equal to
the base with no checkout is still skipped, having nothing to show either way.

A branch not checked out in any worktree is marked `(no worktree)`. It is
diffed by name rather than against HEAD, so it shows committed changes only:
with no working tree there is nothing to be dirty, and its second indicator
slot is always blank.

The branch list costs one git call per session branch, so it is computed on
refresh — panel open, `R`, |:ClaudeDiffRefresh| or a write — and never on a
redraw.

Status indicators                                          *claude-diff-icons*

Each file row in the diff tree carries a bracketed field with two slots: the
first is what the branch did to the file relative to the base, the second what
the working tree has done since.

  [✚]      added on this branch, clean in the working tree
  [✹]      modified on this branch, clean in the working tree
  [ |✹]    untouched by the branch, modified in the working tree
  [✚|✹]    added on this branch and modified since
  (blank)  neither

The empty slot is kept when only the working tree changed: a lone [✹] could
not say which of the two slots it came from.

The glyphs are nerdtree-git-plugin's, so the diff tree and NERDTree label git
state the same way:

  Staged     ✚  (+)   added on the branch, or staged in the index — green
  Modified   ✹  (*)   changed
  Deleted    ✖  (D)   removed — red
  Renamed    ➜  (R)   renamed or copied
  Untracked  ✭  (!)   not known to git

The add and remove glyphs take their colour from |hl-DiffAdd| and
|hl-DiffDelete|, so they follow whatever the colourscheme calls green and red.
Only the foreground is copied: those groups usually carry a background, which
would paint a block behind the glyph.

The bracketed characters are used when |g:claude_panel_ascii| is set.

When nerdtree-git-plugin is installed its `gitstatus#getIndicator()` is called
directly, so `g:NERDTreeGitStatusUseNerdFonts` and any
`g:NERDTreeGitStatusIndicatorMapCustom` carry over. Without it an embedded copy
of its defaults is used; there is no hard dependency either way.

Colours prefer that plugin's own NERDTreeGitStatus* groups when they exist and
otherwise use the groups it links them to, so restyling one restyles the other.
Override any of these to restyle just the diff tree: >
    highlight link ClaudeDiffStaged    Function
    highlight link ClaudeDiffModified  Special
    highlight link ClaudeDiffDeleted   Operator
    highlight link ClaudeDiffRenamed   Title
    highlight link ClaudeDiffUntracked Comment
    highlight link ClaudeDiffUnmerged  Label
<
Note: the tree reads `git diff --name-status`, not `git status --porcelain`,
so staged work cannot be told apart from unstaged and `═ Unmerged` never
appears. Ignored and clean files are not listed.

Sharing a column with NERDTree                                *claude-nerdtree*

The panel and NERDTree are both anchored to the side of the screen, so on
their own they would form two columns and eat most of the window. When both
are open they instead share one column, with the panel on top: >

    +----------------+-------------------------------+
    | Claude Sessions|                               |
    | (panel)        |   your code                   |
    +----------------+                               |
    | NERDTree       |                               |
    |                |                               |
    +----------------+-------------------------------+
<
This happens whichever of the two is opened first, and either can be closed
without disturbing the other — closing NERDTree gives the whole column back to
the panel, and hiding the panel leaves NERDTree with it.

                                                             *claude-sidebars*
The column is sized by percentage of the screen: the session panel takes
|g:claude_panel_height_pct| (25 by default), the diff tree
|g:claude_difftree_height_pct| (40), and whichever sidebar sits at the bottom
— NERDTree when it is installed — absorbs the remaining 35%. Zero either
percentage to go back to a height in lines (|g:claude_panel_height|,
|g:claude_difftree_height|).

Resize any of the windows by hand and it stays as you left it — the sizes are
applied only when the sidebars first come together.

|:ClaudeSidebars|, mapped to <C-a> by default, raises all three at once and
dismisses them again once they are all showing. NERDTree may still reset the column's
*width* on its own, which it does independently of this plugin. While stacked the column is
NERDTree's width (`g:NERDTreeWinSize`), not |g:claude_panel_width|: NERDTree
resets its own width whenever it redraws, so the panel does not fight it.

Set |g:claude_panel_nerdtree_stack| to 0 to keep the two as separate columns.
Stacking also switches itself off on Vim builds without |win_splitmove()|
(before 8.1.1140), and does nothing at all when NERDTree is not installed.

Choosing a session                                       *claude-session-target*

Commands that act on one session — |:ClaudeToggle|, |:ClaudeFocus|,
|:ClaudeClose|, |:ClaudeModel|, |:ClaudeExplain|, |:ClaudeInput| — pick their
target like this:

  1. the session whose terminal holds the cursor, if any;
  2. otherwise the only live session, with no prompt;
  3. otherwise a picker listing the live sessions, most recently used first,
     with a "New session" entry at the end;
  4. otherwise, with nothing running, a new session is started.

The picker uses a popup where available and a numbered |inputlist()| prompt
otherwise.

Names                                                     *claude-session-names*

Starting a session prompts for a name (see |g:claude_session_prompt_name|),
which is passed to the Claude CLI as well, so it also appears in Claude's own
prompt box and /resume picker. Names are stored in |g:claude_session_store| and
survive a Vim restart. Sessions that were never named in Vim fall back to their
timestamp and first message.

7. WORKSPACES                                                *claude-workspaces*

A workspace is a git worktree that a session owns: its own checkout of one
branch, so two sessions can work on two branches at once without fighting over
a single directory.

Creating one~
  Starting a session (|:ClaudeNew|, or `n` in the panel) asks two questions:
>
    Branch (blank for no workspace): <Tab>
    Session name:
<
  The branch completes over local and remote branches, the same list
  |:ClaudeDiffBase| offers. A name that matches nothing is accepted and
  becomes a new branch off the current HEAD; a branch that exists only on a
  remote gets a local tracking branch.

  Between them the two answers decide where the session runs:

  branch + name   a workspace called <name>, checked out on <branch>
  branch only     a workspace named after the branch
  name only       no workspace: the session runs in the selected workspace,
                  or in the current directory
  neither         the same, and the session is left unnamed

  A workspace name is unique within the repository: a name already taken gains
  a number, so a second workspace on `feature-branch` becomes
  `feature-branch-1`, then `feature-branch-2`. Slashes become dashes, so
  `feature/deep` is one directory and not a tree.

  The worktree is created beside the main checkout as <repo>-<name>, or
  wherever |g:claude_workspace_dir| points. Workspaces are remembered across
  Vim restarts in |g:claude_workspace_store|, keyed by repository.

  A branch that already has a checkout is not an error: the session runs in
  that checkout. If it is a workspace the session joins it; if it is a worktree
  you made yourself, it is adopted as a workspace and listed from then on; and
  if it is the main checkout, the session simply runs there.

  Nothing is created when the directory is in the way; you are told, and the
  session runs where you already were.

  Removing a workspace is left to `git worktree remove`. A worktree that is
  gone drops out of the list on its own.

Choosing one~
  |:ClaudeWorkspaces| (or |<leader>cw|) lists the main checkout and every
  workspace, and re-roots NERDTree onto the one you pick so the file tree
  shows that checkout and nothing else. The choice is where sessions started
  without a branch run, and it lasts for this Vim session only.

Unnamed sessions, and the buried tail                            *claude-unnamed*
  Leaving both prompts blank is a real answer: the session goes unnamed and
  Claude names the conversation itself. Sessions carrying a
  `claude <date> <time>` name count as unnamed too — that is what earlier
  versions minted when the prompt was left empty, so nobody ever chose it.

  An unnamed session is not a nameless row. It is labelled by the first thing
  that was asked of it, read from its transcript, and only falls back to its
  id (`(unnamed 4f3c9a02)`) when there is no message yet.

  A finished session is buried — left out of the panel list, the way NERDTree
  leaves out dotfiles — when either is true:

    - nobody named it, or
    - nobody has touched it for |g:claude_panel_stale_days| days.

  A running session is never buried, whatever it is called: the one that is
  waiting for you is the last thing to hide.

  Press `I` in the panel to show the buried ones, and again to put them away.
  Renaming one with `r` un-hides it for good, until it goes stale.

  They are hidden from the panel list only. A buried session still counts in
  the panel header while it runs, still appears in the session pickers, still
  appears in |:ClaudeResume|, and still runs.

8. MODEL SELECTION                                              *claude-models*

|:ClaudeModel| (or |<leader>cm|) presents a numbered list built from
|g:claude_models| and sends `/model <name>` to Claude for the chosen entry.
You can call this at any point during a session to switch models
mid-conversation. Opens a new session first if none is running.

9. INPUT WINDOW                                                   *claude-input*

|:ClaudeInput| (or |<leader>ci|) toggles a dedicated buffer for composing
multi-line prompts. A 10-line horizontal split opens at the bottom of the
screen.

Pressing |<leader>ci| again discards the content and closes the window.
To preserve work-in-progress text, press CTRL-C instead — it saves the current
text as a draft and hides the window. The draft is automatically restored the
next time the window opens.

The window opens in insert mode, so <Esc> is left to do what it always does:
leave insert mode. Press it, then CTRL-C, or CTRL-C twice.

The buffer is backed by a temporary `.md` file, so filetype-aware features
work: syntax highlighting, spell checking, and Copilot completions (if
vim-copilot is installed).

Keys inside the input window~
  <C-s>    Send the buffer contents to Claude and close the window.
           Opens a new session automatically if Claude is not running.
  <C-c>    Save the draft and hide the window (normal mode).
  q        Discard the draft and close (normal mode).

Completions~
  /        Trigger slash-command completion. Built-in Claude commands plus
           any custom commands found in `.claude/commands/` (project-level)
           or `~/.claude/commands/` (user-level) are listed.
  @        Trigger file and agent completion. File completions require `rg`
           (ripgrep) on $PATH and honour `.gitignore`. Both full-path and
           basename prefix matches are returned (e.g. `@cla` will match
           `doc/claude.txt`). Custom agents from `.claude/agents/` and
           `~/.claude/agents/` are also listed.

Sending behaviour~
  Text is sent using the same bracketed-paste mechanism as |:ClaudeExplain|,
  so embedded newlines are preserved and do not trigger premature submission.
  If Claude is not yet running, the plugin opens a session and waits up to
  4.5 seconds for it to initialise before sending. After sending, the cursor
  moves to the Claude terminal automatically.
